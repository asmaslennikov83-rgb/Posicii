# Telegram-бот: поисковые запросы и позиции WB

Отдельный проект. Существующий бот `wb_backup` и его конфигурация не меняются.

Сборка **1.0.4**: после средней позиции за 30 дней добавлены семь дат — от вчера до семи дней назад по Москве. В ячейках средняя позиция WB за соответствующий день по каждому запросу. Данные получаются отдельным запросом `POST /api/v2/search-report/product/orders` для объединения запросов двух топов (до 20 уникальных запросов на карточку). Пустое или нулевое значение позиции WB отображается пустой ячейкой. Ошибка дневной аналитики не отменяет 30-дневный отчёт: причина указывается в статусе. Результаты дневного запроса также сохраняются в JSON рядом с Excel. Дополнительный запрос учитывает интервал API, поэтому отчёт может формироваться дольше.

Сборка **1.0.3**: добавлены код ошибки, этап, тип и место сбоя в журнале без значений исключений и токенов. Неожиданная ошибка каталога одного кабинета не прерывает отчёт другого. Пустые размеры и списки ШК обрабатываются без падения. Точную причину старого сообщения без диагностики установить нельзя.

В 1.0.2 исправлен запуск при распаковке файлов непосредственно в `/app`.
Если файлы `bot.py`, `main.py`, `config.py` лежат в корне проекта сервера,
команда запуска — `python main.py`. Также поддерживаются `python -m bot` и `python bot.py`.
Если сохранена папка `wb_positions`, запуск из родительской папки — `python -m wb_positions`.
Версия отображается в нижней строке меню; после обновления отправьте `/start`, чтобы обновить кнопки.

## Что работает

- Доступ только по белому списку Telegram user ID и только в личных чатах.
- Ввод одного ШК или артикула продавца текстом, запуск кнопкой «Сформировать отчёты».
- Полная загрузка актуального каталога каждого кабинета с пагинацией. Проверяются все `sizes[].skus[]`.
- Поиск точного совпадения; ведущие нули ШК сохраняются. По найденному товару добавляются все карточки с тем же артикулом продавца и связанными ШК в обоих кабинетах. Артикулы WB между кабинетами могут отличаться.
- Статистика отдельно на каждую карточку WB. Несколько ШК одной карточки не складываются и не дублируют переходы.
- Период: 30 завершённых календарных дней по Москве, заканчивается вчера. Например, запуск 29 октября 2026 — 29 сентября–28 октября включительно.
- Два отдельных Excel-файла, в каждом два листа: топ-10 по переходам и топ-10 по частотности. Ранжирование отдельно для каждого артикула WB.
- Независимая обработка двух кабинетов, повтор временных ошибок, соблюдение интервалов API, защита от повторного нажатия.
- Файлы и исходная выборка JSON сохраняются на диске. Очередь в памяти: после перезапуска незавершённый запрос нужно отправить повторно. Расписания нет.

## Существенные ограничения текущей версии

**Это рабочая основа, а не завершённый мониторинг всех позиций.**

1. `search-report/product/search-texts` выбирает до 30 запросов (до 100 на подходящем тарифе) по переходам. Поэтому топ-10 по переходам получается из API, а топ по частотности — только **среди доступной выборки**. Даже если пришло менее лимита, полнота не предполагается. CSV-метод WB также имеет параметры `topOrderBy` и `limit`, его нельзя автоматически считать полной выгрузкой.
2. Общая средняя позиция WB за период не равна органической позиции. Бот не вычисляет органическую позицию вычитанием рекламы.
3. Встроенного источника раздельных органических/рекламных позиций пока нет. Эти столбцы остаются пустыми с явным статусом. Можно подключить локальный импорт результатов стороннего мониторинга (формат ниже); его получение и проверка требуют отдельного подключения поставщика данных.
4. Доступ к поисковой аналитике зависит от прав и тарифа каждого кабинета. Наличие API-ключа само по себе не гарантирует доступ. Тарифы и ограничения нужно проверить на реальных кабинетах.
5. Карточки из корзины WB не участвуют: штатный метод каталога их не возвращает.
6. Проверки выполнены на имитации ответов API. Для проверки на реальных данных необходимы секреты и активный бот.

## Быстрый запуск Windows

Команды выполняются из родительской папки проекта, содержащей каталог `wb_positions`.

```powershell
py -3.12 -m venv .venv_positions
.\.venv_positions\Scripts\python.exe -m pip install -r .\wb_positions\requirements.txt
Copy-Item .\wb_positions\.env.example .\wb_positions\.env
notepad .\wb_positions\.env
.\.venv_positions\Scripts\python.exe -m wb_positions
```

В `.env` заполнить:

- `TELEGRAM_BOT_TOKEN`: токен отдельного бота от BotFather. Не используйте одновременно один токен для старого и нового бота.
- `ALLOWED_USER_IDS`: числовые ID через запятую. Пример: `123456789,987654321`.
- `WB_1_NAME`, `WB_2_NAME`: названия кабинетов.
- `WB_1_TOKEN`, `WB_2_TOKEN`: по одному ключу каждого кабинета с правами на Контент и Аналитику.
- `WB_QUERY_LIMIT=30`. Установить `100` только после проверки тарифа Джем.
- `WB_ANALYTICS_INTERVAL=21`: подходит для лимита 3 запроса в минуту. Если используется базовый токен с лимитом 1 запрос в час, указать `3601`; такие отчёты будут формироваться долго.

Бот читает только `wb_positions/.env`, родительский `.env` другого бота не загружается. Переменные окружения сервера имеют приоритет. Ключи не отправляются в Telegram и не записываются в отчёты. Не включайте отладочное логирование HTTP, оно может раскрыть токен Telegram в URL.

При первом запуске бот пропускает накопившиеся Telegram-сообщения. Затем открыть бота, отправить `/start`, ввести ШК или артикул и нажать кнопку. При ошибках доступа файл содержит пояснение вместо выдуманных значений. Если не получен каталог целого кабинета, бот сообщает об этом отдельным сообщением.

## Docker

Из папки `wb_positions`, после заполнения `.env`:

```powershell
docker compose up -d --build
docker compose logs --tail 50
```

Папка `data` подключена как постоянный диск. На одном токене Telegram должен работать только один процесс. Каталог `data/reports` содержит отчёты и растёт со временем — удаляйте ненужные старые файлы самостоятельно.

## Дополнительные источники

Это необязательный интерфейс импорта, а не уже подключённый внешний сервис. Папки отдельно для каждого кабинета: `data/imports/1/` и `data/imports/2/`. Файлы должны обновляться оператором или отдельной интеграцией **до** нажатия кнопки, желательно атомарной заменой. Артикул `nm_id` — именно артикул WB соответствующего кабинета.

Для полной выборки запросов нужны **оба** файла `queries.csv` и `queries.json`. CSV UTF-8, разделитель запятая, числовые показатели без разделителей тысяч:

```csv
nm_id,query,open_card,frequency,avg_position
123456789,женская футболка,352,82500,18.5
```

Манифест подтверждает полный охват указанных карточек и точное совпадение периода. `complete: true` допустимо указывать только если источник действительно предоставляет все запросы. Пустая выборка при таком подтверждении означает отсутствие запросов.

```json
{"start":"2026-09-29","end":"2026-10-28","complete":true,"source":"Название проверенного источника","nm_ids":[123456789]}
```

При несовпадающих датах или отсутствии карточки в манифесте бот использует ограниченную выборку WB и явно указывает это. Повреждённый импорт вызывает ошибку карточки, а не скрытую подмену данных.

Для раздельных позиций файл `positions.csv`, UTF-8:

```csv
nm_id,query,organic_position,ad_position,measured_at,region,source
123456789,женская футболка,25,7,2026-10-29T12:00:00+03:00,Москва,Название мониторинга
```

Пустое значение позиции означает «нет данных», а не нулевую позицию. Для одинакового запроса и карточки берётся самый поздний замер. Дата с часовым поясом, регион и источник обязательны и видны в отчёте. Это отдельный замер, не средняя позиция за 30 дней. Старые замеры не выдаются за свежие: в Excel всегда указан их фактический момент.

## Проверки

```powershell
.\.venv_positions\Scripts\python.exe -m unittest discover -s wb_positions/tests -v
```

Проверены: доступ, все ШК размеров и ведущие нули, несколько карточек, сопоставление кабинетов, пагинация и повтор курсора, повтор 429, обработка ошибок прав, период по Москве, отсутствие дублей заданий, независимые файлы, Excel и импорт дополнительных данных.

## Источники контрактов API

- [Аналитика WB](https://dev.wildberries.cn/docs/openapi/analytics): выборка запросов, ограничения и CSV.
- [Каталог WB](https://dev.wildberries.cn/docs/openapi/item-management): карточки, размеры, пагинация.

Документация проверена 29 октября 2026. Используется официальная документация китайского зеркала из-за недоступности русского сайта при проверке; рабочие запросы направляются только на российские хосты `*.wildberries.ru`.
